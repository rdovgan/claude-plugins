# domain-export

Phase 6. The only writes outside the workspace this plugin makes. The guard allows creating pages only in the configured space under the configured parent (or under a page qa-docs created), updating only pages qa-docs created, and one footer comment on the old page a mirror was made from; Claude Code asks the user to approve each call.

## Pages

- Layout `domain`: `doc/README.md` is the domain page, under the configured parent. Its children, in this order: the process pages in the order the README lists them, then `reference/rules.md`, `states.md`, `data.md`, `config.md`, `integrations.md`, `differences.md`, `open-questions.md` (only those that exist). Page titles: the `#` heading of each file; prefix the children with the domain title when Confluence needs unique titles in the space ("Bookings: Cancellation").
- Layout `mirror`: `doc/page.md` is the page, under the configured parent, titled "<old title> (<date in the document language>)", for example "Reservations (as of 2026-10-22)"; `doc/changes.md` is its child. The old page is never edited.

## Steps

1. Read `qa-docs/domains/<slug>/meta.json`. Export only `verified` or `exported` documents; otherwise say what is missing and offer `/qa-docs:verify <slug>`. If a repository in `modules` has a newer commit now (session context lists changed domains), say so and recommend `/qa-docs:refresh <slug>` first; export only if the user insists. An old single-file document (`domain.md`, no `doc/`): offer `/qa-docs:rewrite <slug>` first.
2. The target comes from the session context (the export line) or `.qa-docs/config.env`: cloud, space, parent page. If it is not configured, stop and tell the user to ask the admin.
3. Run `${CLAUDE_PLUGIN_ROOT}/scripts/render-diagrams.sh qa-docs/domains/<slug> --check`. Outdated or missing PNGs: render them first (without the check flag).
4. **Manual edits in Confluence.** For every page that has an id in `confluence.pages` (and the root `confluence.pageId`), read it (`getConfluencePage`, `contentFormat: markdown`) and compare it with `export/last-export/<doc path>` (a document exported before qa-docs 0.3.0 kept the root page body in `export/last-export.md`). If people changed any, show the differences per page and ask once with `AskUserQuestion`: "Bring their edits into the document first" (Recommended: check each edit against the code, add what is right to the page in `doc/`, record what is wrong in the differences) / "Overwrite their edits" / "Cancel".
5. **Build each body** from its file in markdown:
   - The root page starts with a note: "Generated by qa-docs from code at <repo@commit, ...>, verified by <who> on <date>. Changes go through qa-docs; manual edits are kept only if brought into the document. Diagram pictures (PNG) are on the qa-docs server in `qa-docs/domains/<slug>/doc/diagrams/`." (in the document language). Child pages start with their "Part of ..." line.
   - Diagrams: the MCP server cannot upload attachments, so the PNGs stay on the server. Replace each picture line `![Title](.../diagrams/<name>.png)` with one line: "**<Title>** - picture: `qa-docs/domains/<slug>/doc/diagrams/<name>.png` on the qa-docs server; the mermaid source below opens in mermaid.live." (in the document language), and keep the ```` ```mermaid ```` block as a code block.
   - Links between pages: `[text](<relative>.md#anchor)` becomes a link to that page's Confluence URL (from `confluence.pages`, without the anchor). A page that does not exist in Confluence yet: see step 6.
   - Remove the HTML anchors (`<a id="br1"></a>`); code references stay as inline code.
6. **Publish** with `contentFormat: "markdown"` and the cloud id from the config (or `getAccessibleAtlassianResources`):
   - Create the pages that have no id yet, root first, then children with `parentId` = the root page id; for the first creation of a page whose links point at pages not created yet, use a body with only its title line and fill it in the next pass. Save every new id and URL into `meta.json` (`confluence.pageId`/`url` for the root, `confluence.pages["<doc path>"]` for the others) **right after each call**, so a broken session does not lose them.
   - Then `updateConfluencePage` every page with its final body and a `versionMessage` naming the commits.
   - A page in `confluence.pages` whose file no longer exists: update its body to one line saying it is no longer part of the document, with a link to the root page, and tell the user to delete or archive it in Confluence (qa-docs does not delete pages).
7. **Mirror only, first export only** (`confluence.sourceCommentId` is empty): add a footer comment on the old page (`createConfluenceFooterComment`, `pageId` = `source.pageId`): "An updated version of this page, checked against the code at <date>: <new page link>. What changed: <changes page link>." (in the document language). Save the comment id to `confluence.sourceCommentId`. If the user or the guard refuses it, say so and continue: the export itself is done.
8. Save exactly the body you sent for each page to `export/last-export/<doc path>` (for example `export/last-export/flows/cancel.md`). Update `meta.json`: `status` = `exported`, `confluence.exportedAt`, `confluence.exportedModules` (copy of `modules`). Append a `history.md` entry with the links.
9. Finish with the root page link in one line, and the number of pages created and updated.

If a call is refused by the guard or the user, report it and stop; do not try another tool or another space.
