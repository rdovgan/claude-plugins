# domain-export

Phase 6. The only writes outside the workspace this plugin makes: pages through the MCP server, and diagram attachments of those pages through `confluence-attach.sh` (REST API, the user's own token). The guard allows creating pages only in the configured space under the configured parent (or under a page qa-docs created), updating only pages qa-docs created, and one footer comment on the old page a mirror was made from; Claude Code asks the user to approve each call.

## Pages

The pages are the files of `confluence/`, built by `domain-confluence` from `doc/`; `confluence/pages.json` gives each page's title, the `doc/` page it comes from, and its parent. They are sent as they are (`contentFormat: "html"`), so what the user saw in `confluence/preview/` is what Confluence shows. Page ids are kept in `meta.json` by the `doc/` path, as before: `confluence.pageId`/`url` for the root, `confluence.pages["<doc path>"]` for the others (for example `flows/cancel.md`), so documents exported by older versions keep their pages.

- Layout `domain`: `index.html` is the domain page, under the configured parent; the others are its children in the order of `pages.json`.
- Layout `mirror`: `page.html` is the page, under the configured parent, titled "<old title> (<date in the document language>)", for example "Reservations (as of 2026-10-22)"; `changes.html` is its child. The old page is never edited.

## Steps

1. Read `qa-docs/domains/<slug>/meta.json`. Export only `verified` or `exported` documents; otherwise say what is missing and offer `/qa-docs:verify <slug>`. If a repository in `modules` has a newer commit now (session context lists changed domains), say so and recommend `/qa-docs:refresh <slug>` first; export only if the user insists. An old single-file document (`domain.md`, no `doc/`): offer `/qa-docs:rewrite <slug>` first.
2. The target comes from the session context (the export line) or `.qa-docs/config.env`: cloud, space, parent page. If it is not configured, stop and tell the user to ask the admin.
3. Run `${CLAUDE_PLUGIN_ROOT}/scripts/render-diagrams.sh qa-docs/domains/<slug> --check`, then `${CLAUDE_PLUGIN_ROOT}/scripts/confluence-pages.sh qa-docs/domains/<slug> --check`. Outdated or missing PNGs: render them. No `confluence/`, or pages older than `doc/`: run `domain-confluence` first, then show the user where the preview is and continue.
4. **Manual edits in Confluence.** For every page that has an id in `meta.json`, read it (`getConfluencePage`, `contentFormat: markdown`) and compare it with `export/last-export/<doc path>` (the page as read back after the last export; a document exported before qa-docs 0.3.0 kept the root page in `export/last-export.md`). If people changed any, show the differences per page and ask once with `AskUserQuestion`: "Bring their edits into the document first" (Recommended: check each edit against the code, add what is right to `doc/` and rebuild `confluence/`, record what is wrong in the differences) / "Overwrite their edits" / "Cancel".
5. **Create the missing pages** with `contentFormat: "html"` and the cloud id from the config (or `getAccessibleAtlassianResources`): root first, then the children with `parentId` = the root page id, each with a body of one paragraph (its first info panel text is enough), because its links and pictures need page ids that do not exist yet. Save every new id and URL into `meta.json` **right after each call**, so a broken session does not lose them.
6. **Pictures.** For every page with diagrams run `${CLAUDE_PLUGIN_ROOT}/scripts/confluence-attach.sh qa-docs/domains/<slug> <file.html>`. It uploads the PNGs as attachments of that page with the user's API token and records them in `meta.json` (unchanged PNGs are not uploaded again). Exit 3 means the token is not set: tell the user once how to set it (`QA_DOCS_CONFLUENCE_EMAIL`, `QA_DOCS_CONFLUENCE_TOKEN`, see `server/README.md`) and ask with `AskUserQuestion` whether to publish now with picture paths instead ("Publish without pictures" / "Stop, I will set the token"). Any other failure: report it and use `--no-images` for that page.
7. **Bodies.** For every page run `${CLAUDE_PLUGIN_ROOT}/scripts/confluence-body.sh qa-docs/domains/<slug> <file.html>` (with `--no-images` per step 6). It writes `export/outgoing/<file.html>` with the pictures and the page links resolved, or names what is missing. Read that file and send it unchanged with `updateConfluencePage` (`contentFormat: "html"`, title from `pages.json`, `versionMessage` naming the commits). Do not edit the body on the way: a change belongs in `doc/` and `confluence/`.
   - The guard and the user approve each call. If the server rejects a body as invalid HTML, fix the page in `confluence/` (the error names the node), run `confluence-pages.sh`, and send it again.
   - A page in `meta.json` whose file is no longer in `pages.json`: update its body to one paragraph saying it is no longer part of the document, with a link to the root page, and tell the user to delete or archive it in Confluence (qa-docs does not delete pages).
8. **Mirror only, first export only** (`confluence.sourceCommentId` is empty): add a footer comment on the old page (`createConfluenceFooterComment`, `pageId` = `source.pageId`): "An updated version of this page, checked against the code at <date>: <new page link>. What changed: <changes page link>." (in the document language). Save the comment id to `confluence.sourceCommentId`. If the user or the guard refuses it, say so and continue: the export itself is done.
9. Read every published page back (`getConfluencePage`, `contentFormat: markdown`) and save it to `export/last-export/<doc path>`: the next export compares against this. Update `meta.json`: `status` = `exported`, `confluence.exportedAt`, `confluence.exportedModules` (copy of `modules`). Append a `history.md` entry with the links.
10. Finish with the root page link in one line, the number of pages created and updated, and whether the pictures were uploaded.

If a call is refused by the guard or the user, report it and stop; do not try another tool or another space.
